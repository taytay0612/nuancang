# 云端版要你在后台做的 3 件事

页面已经做好，地址是 `http://127.0.0.1:8787/?mode=cloud`（或窗口里打印的局域网地址加 `/?mode=cloud`）。

## 1. 建表并授权

Supabase 控制台 → 左侧 `SQL Editor` → `New query` → 粘贴 `supabase_setup.sql` 全文 → 点 `Run`。

成功的标志：底部显示 `Success. No rows returned`。

这一步补的是当前缺的权限。现在用公开密钥读 `nuancang_spaces` 会报 `permission denied`，因为表建好了但没给 `authenticated` 角色授权。

## 2. 建一个家庭账号

新版控制台的 Email 页面（Authentication → Sign In / Providers → Email）没有 `Confirm email` 开关，只有密码位数、OTP 那些选项。这一版 `Confirm email` 挪到了 Authentication → Settings 里；但不用去找它，直接建账号更快：

1. Authentication → Users → 右上角 `Add user` → `Create new user`。
2. 填邮箱和密码（至少 6 位）。
3. 勾上 `Auto Confirm User`。
4. 点 `Create user`。

这样账号建出来就是已验证状态，App 里直接登录即可，不受 `Confirm email` 设置影响。

如果之前已经在 App 里点过「创建账号」，Users 里会有一条未验证的记录。到那条记录右侧菜单点 `Confirm email`，或者删掉重建。

想以后在 App 里自助注册，再关 `Confirm email`：Authentication → Settings → 找 `Confirm email` 开关关掉。

## 3. 可选：GitHub 登录

先不要配。这台机器直连 `github.com` 会被重置，点 GitHub 登录会停在浏览器的错误页。要用 GitHub，得先让电脑能稳定访问 GitHub，再去 GitHub → Settings → Developer settings → OAuth Apps 建应用，回调填：

```
https://yozswbcoesmhstywbzhg.supabase.co/auth/v1/callback
```

然后把 Client ID 和 Secret 填进 Authentication → Providers → GitHub。

## 之后怎么用

1. 双击 `启动暖仓.bat`。
2. 浏览器打开 `http://127.0.0.1:8787/?mode=cloud`。
3. 点「创建账号」，填一个家庭共用邮箱和密码。
4. 以后每台设备打开同一个地址，用这个邮箱密码登录，看到的是同一份数据。

## 说明

- 一个账号一份数据。家里人要看到同一份，就用同一个邮箱密码。
- 数据存在 Supabase 的 `public.nuancang_spaces` 表，`data` 字段是整份 JSON。
- 页面不加载任何外部脚本，国内网络能直接用。
- 登录状态存在浏览器本地，换浏览器要重新登录。

## 如果报错

| 提示 | 原因 | 处理 |
|---|---|---|
| 数据库没有授权 | 第 1 步没做或没成功 | 重跑 `supabase_setup.sql` |
| 云端表不存在 | 同上 | 同上 |
| Invalid login credentials | 账号不存在或密码错 | 先点「创建账号」 |
| 账号已创建，但还要求邮箱验证 | `Confirm email` 没关 | 做第 2 步 |
